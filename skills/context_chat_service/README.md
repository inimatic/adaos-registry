# Context Chat

Локальное приложение AdaOS для одного владельца: проекты, текстовый чат через
личный ChatGPT, документы и редактируемая память проекта. Целевая платформа
beta 0.4 — локальный Windows-компьютер с браузером на том же компьютере.
Удалённая VM с браузером на другом устройстве и многопользовательский доступ
в эту версию не входят.

## Данные и интерфейс

Основной интерфейс описан в `webui.json` тремя нативными компонентами клиента:
`collection.projectList`, `ui.projectConversation`, `item.conversationContext`.
Расположение панелей, общая сессия сервиса, аккаунт, форматы файлов и интервал
обновления задаются декларативно. Цвета наследуются от текущей темы AdaOS.
Приложение не использует iframe. Запросы идут через авторизованный транспорт
активного узла, включая Root-маршрут из inimatic.com; пятиминутной cookie нет.
Сам сервис слушает loopback и отклоняет сторонние сайты и нелокальные имена
хоста. HTML-интерфейс в web/ оставлен для совместимости и отдельных проверок.
Пакет запрашивает только `storage.relational`; общий доступ к workspace
не требуется. Настройки аккаунта не выдаются браузеру.

Проекты, история, тексты источников и память хранятся в SQLite runtime.
OAuth-токены — в зашифрованном файле runtime; небольшой ключ шифрования
хранится в хранилище учётных данных ОС и привязан к устойчивому
идентификатору хоста, а не к версии пакета. Пакет приложения не содержит
пользовательских данных или учётных данных.

Поддерживаются TXT, Markdown, JSON, CSV, HTML, LOG, DOCX, XLSX и PDF до 10 МБ каждый.
Файлы можно выбрать в меню «+» или перетащить на область чата. Они становятся
текстовыми источниками проекта и вложениями черновика. DOCX нормализуется в
Markdown: сохраняются заголовки, списки, таблицы, выделения и внешние ссылки.
XLSX представлен заголовками листов и таблицами «ячейка — значение»; PDF —
разделами с номерами страниц и извлечённым текстом. Вёрстка PDF, его таблицы
и стили автоматически точно не восстанавливаются. Из каждого файла
извлекается до 160000 символов. XLSX читается по листам с адресами ячеек;
формулы не вычисляются, используются сохранённые результаты. Внешние связи
не загружаются. Лимиты распаковки XLSX: 32 МБ суммарно, 8 МБ на XML, 100000 ячеек.
PDF извлекается постранично в отдельном процессе: до 500 страниц, 512 МБ памяти
и 30 секунд. Ссылки, вложения и скрипты PDF не исполняются. Для сканов без
текстового слоя требуется предварительный OCR; картинки PDF и DOCX не анализируются.

Переписка показывается окнами по 50 сообщений, с переходами к предыдущим,
следующим и последним сообщениям. Опрос сохраняет выбранное старое окно.
Полная история хранится в базе и попадает в экспорт. Контекст модели формируется
отдельно: память проекта, включённые источники и последние завершённые сообщения
(до 200, в пределах общего бюджета 160000 символов с резервом для нового запроса).
Старые сообщения автоматически выходят из окна модели; их важные факты могут
сохраняться в памяти. При отключённом обновлении памяти резюме не обновляется.
Если сами память и источники заполняют бюджет, приложение предлагает исключить
лишние источники. Это прикладной бюджет символов, а не точный токеновый лимит модели.

В меню «+» включается веб-поиск Responses API (`web_search`, beta). Разрешение
хранится отдельно для проекта и видно рядом с полем ввода. Модель решает, когда
искать; ссылки из аннотаций ответа отображаются в тексте. Поддержка инструмента
зависит от модели и разрешений аккаунта. При отказе OpenAI нет скрытого повтора
без поиска: пользователь получает объяснение. MCP в этой версии не подключается.

Память содержит предысторию, предпочтения и договорённости. Её можно
редактировать вручную и обновлять моделью. Автоматическое обновление после
общения включено по умолчанию и отключается видимым переключателем.
Добавление источника помечает память к обновлению, сохраняя ручные правки.
Исключение или удаление источника сбрасывает память; история остаётся видимой.
Сравнение версий защищает ручную правку от более старого фонового результата.

Черновик хранится в sessionStorage текущей вкладки отдельно для каждого
проекта и переживает перезагрузку интерфейса. После отправки или удаления
проекта он удаляется. Закрытие вкладки завершает её браузерную сессию.

«Экспорт проекта» скачивает JSON с историей, текстами источников и памятью.
Он не содержит настроек аккаунта и OAuth-токенов, но содержит личные данные
проекта. Автоматический импорт такого архива пока не реализован.

## Подключение ChatGPT

Вход использует официальный Authorization Code + PKCE/OIDC и HTTP callback
на `127.0.0.1` компьютера runtime. Проверяются state, подпись ID token,
issuer, audience, срок действия, nonce и разрешение `chatgpt.tokens.use.direct`.
Зашифрованные учётные данные заменяются атомарно; ключ остаётся в хранилище
ОС. Refresh token обновляется с ротацией. При отзыве сессии интерфейс требует
повторного входа.

Каталог моделей загружается для подключённого аккаунта. Inference использует
публичный Responses API с `store: false`, `stream: true`. Успех подтверждается
только непустым текстовым ответом и событием `response.completed`.
Приложение не читает существующие чаты и память аккаунта ChatGPT.

«Проверить доступ к чату» запускает реальный короткий запрос без содержимого
проектов. Подтверждение доступа появляется только после завершённого ответа.
Логин и каталог моделей отдельно не подтверждают работоспособность inference.
Первую реальную авторизацию выполняет владелец в браузере. Автоматические
тесты используют подменённый транспорт и не доказывают доступ его подписки.

## Надёжность

Модель и контекст фиксируются перед запуском worker. Идемпотентный ключ
защищает от повторной отправки после потери HTTP-ответа. Повтор последнего
неудачного ответа использует исходное сообщение без дублирования истории.
Отмена блокирует поздние записи worker. После перезапуска частичный ответ
сохраняется со статусом прерванного. Миграция v2 сохраняет данные и checksum
исходной миграции v1. Неудача обновления памяти сохраняет успешный ответ
и прежнюю память с понятным предупреждением.

Native lifecycle содержит реальные `drain_runtime` и `rehydrate_runtime`.
Перед остановкой проверяются владелец data root, PID и одноразовый nonce.
Обработчик дожидается выхода именно этого процесса; чужой сервис не
останавливается. Маркер обслуживания блокирует новые записи и открытие базы
при автоматическом перезапуске до восстановления. Зашифрованная сессия
объявлена как ограниченный opaque state file, служебные маркеры — как
координационные файлы. Необъявленные файлы блокируют перенос данных.

Для локальной beta используется один эффективный service runtime приложения.
Супервизируемый bootstrap может быть привязан владельцем к неизменяемому
Candidate через `internal/context-chat-binding.json`. Привязка проверяет
Application, компонент, digest релиза, границы приватного runtime и хеши
исходников. Затем запускается код закреплённого пакета с его собственным
data root. Браузер не может изменить эту привязку. Это позволяет обслуживать
выбранную beta через существующий service gateway. Общий gateway поддерживает
явный авторизационный заголовок для нативных запросов; cookie-защита старого
HTML-интерфейса сохраняется.
Preview того же приложения использует этот же эффективный backend.

Локальный журнал ограничен 2000 событиями изменения. Записываются только
шаблон маршрута, метод, HTTP-результат и время — без содержимого запросов,
query, файлов или токенов.

## External effects

Только явное действие `Continue with ChatGPT` начинает авторизацию у OpenAI.
Отправка сообщения передаёт выбранной модели историю, память, включённые
источники проекта и явные вложения. Проверка доступа передаёт только короткий
тестовый запрос. Обновление памяти — отдельный inference-запрос с расходом
плана. Автоматическое обновление управляется видимым переключателем.
Экспорт создаёт локальный файл по нажатию пользователя.

Отключение удаляет локальную сессию и пытается отозвать refresh token.
Если отзыв не подтверждён, интерфейс предлагает отключить приложение
в настройках ChatGPT. Локальные проекты при отключении сохраняются.

## Проверки и ограничения

Backend-проверки: `tests/test_context_chat.py`. Используются временные базы
и подмена внешнего транспорта. Нативные browser-проверки:
`tests/native-browser.mjs`; совместимость HTML: `tests/browser.mjs`.
Они проверяют реальный локальный CRUD и удаляют только свои тестовые проекты.
Страницы провайдера и ответ начала OAuth подменяются только в тестах открытия
новой вкладки с COOP. Уведомления других приложений не открываются автоматически
в тестовом браузере. Эти проверки не подтверждают реальный вход в ChatGPT.
Ни один автоматический тест не выполняет вход и не расходует inference-квоту.

Нативный интерфейс требует клиент 0.0.474 или новее. Запросы используют
текущую авторизацию узла, без отдельной UI-cookie. При потере связи интерфейс
сохраняет показанную переписку и черновик и предлагает повторить подключение.
Диалоги размещаются общим плавающим слоем вне изолированных колонок.

Не поддерживаются PDF, изображения, аудио, видео, внешние инструменты модели,
чтение чатов ChatGPT и автоматическое получение ленты социальной сети.
Экспорт ленты добавляется пользователем как текстовый источник.
